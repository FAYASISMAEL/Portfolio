# Fayas Ismael's Portfolio

The existing portfolio, refactored into HTML, CSS and vanilla JavaScript with an Express server and persistent SQLite content management. The original colors, fonts, project cards, experience rows and animations are retained. `portfolio.html` and the original screenshots are preserved as reference files; the server redirects the old `/portfolio.html` URL to the new homepage.

## Requirements and setup

Use **Node.js 22.14 or newer** (Node 24 LTS recommended) and npm. SQLite uses Node's built-in `node:sqlite`; there is no database service or native SQLite addon to install. Early Node 22 versions print an experimental SQLite warning.

This computer also has Node 20 installed. The npm commands automatically use a compatible Node version already installed through nvm, even if the shell still uses Node 20. This does not change your global Node version. If no compatible runtime is installed, install Node 22.14+ or select it with `nvm use 22.14.0`.

```sh
npm install
npm run setup:admin
npm run dev
```

Open `http://localhost:3000`. The frontend and backend run together; do not open the HTML files directly or use a separate static-file server.

The setup command asks for a username and a password of at least 12 characters, with confirmation. Password input is hidden. It creates `.env` using `.env.example`, stores a salted scrypt hash, and generates a random session secret. There are no default credentials. `.env` is ignored by Git and is never served. Run setup again and restart to change credentials and invalidate old sessions. Do not share or commit `.env`.

For production, use `npm start` instead of the watch-mode development command.

## Pages and content management

- `/index.html`: existing personal content, database-driven experience and up to three featured projects.
- `/works.html`: every project in display order, including RiverGuard.
- `/edit.html`: login screen when signed out; protected dashboard when signed in.

The dashboard can create, edit, delete and reorder both projects and experiences. Deletion requires confirmation. Project technologies and experience tags are comma-separated. Turn on “Currently Working Here” for a Present end date.

The first three existing projects are initially featured. At most three can be featured, enforced both in the UI and by the server. Unfeature one before featuring another. If none are featured, the homepage shows the three most recently created projects. Move Up / Move Down controls Works order, the relative order of featured projects, and experience order.

Changes save to the database immediately. Public pages fetch current data on load, on tab focus, and after an edit in another same-origin browser tab. Visitors on other devices see updates on their next load or focus; this is not a continuous push service.

Your existing About, skills, contact information, social links and Formspree endpoint remain in `index.html`. Projects and experience are managed entirely through the dashboard.

## Environment variables

- `ADMIN_USERNAME`: login username or email.
- `ADMIN_PASSWORD_HASH`: scrypt hash generated by setup. Never use the raw password here.
- `SESSION_SECRET`: random value generated by setup; at least 32 characters.
- `PORT`: HTTP port, default `3000`.
- `HOST`: bind address, default `127.0.0.1`; set `0.0.0.0` in a container or managed host.
- `NODE_ENV`: `development` locally; `production` for deployment.
- `SITE_URL`: exact public origin, such as `https://portfolio.example.com`, without a path or trailing slash. Must use HTTPS in production. It is also used for absolute social-preview image URLs and request-origin checks. Visit that origin when using the admin page.
- `TRUST_PROXY`: default `0`; set `1` only when exactly one trusted reverse proxy handles traffic before the app. This affects secure cookies and rate limiting.
- `DATABASE_PATH`: default `./storage/portfolio.sqlite`.
- `UPLOAD_DIR`: default `./uploads/projects`.

## Database and backups

On first startup, the server seeds SQLite from `data/portfolio-data.json`. A seed marker prevents reseeding after intentional deletions. Editing the seed file later does not overwrite saved content. Content and order changes are committed transactionally; sessions also persist in SQLite and expire after eight hours.

Back up both the database and uploaded images. The simplest consistent backup is to stop the app, copy the entire `storage/` and `uploads/projects/` directories, then restart. SQLite uses WAL mode: do not copy only the `.sqlite` file while the app is writing. Restore both directories together.

## Images

Upload one PNG, JPG/JPEG or WebP file, up to 5 MB. The browser previews the file without embedding Base64 in HTML. The server checks the decoded format, limits dimensions to 40 megapixels, rotates/resizes to fit within 1920 × 1920, strips metadata, and re-encodes to WebP. Filenames are random UUIDs; client filenames are not used for storage.

The database stores the public image URL. Missing or broken images show a fallback in the existing project visual area. Images from canceled saves or deleted/replaced projects are retained deliberately; review unused files before deleting them, since images may be shared or needed for restoration.

RiverGuard originally had no image or URL, so it retains the fallback and has no empty action link. Hope Foundation's existing `the-nurse-boy` GitHub link is preserved; update it in the dashboard if it is not the intended repository. No project destinations were invented.

## API

Public GET requests: `/api/projects`, `/api/experience`.

Authenticated operations for each collection:

```text
POST   /api/projects               Create
PUT    /api/projects/:id           Replace editable fields
DELETE /api/projects/:id           Delete
PUT    /api/projects/reorder        { "ids": [all current IDs in desired order] }

POST   /api/experience
PUT    /api/experience/:id
DELETE /api/experience/:id
PUT    /api/experience/reorder

POST   /api/uploads                multipart/form-data, field: image
GET    /api/auth/session           Session state and CSRF token
POST   /api/auth/login             { "username": "...", "password": "..." }
POST   /api/auth/logout
```

All writes, including login, need the session's `X-CSRF-Token`. Admin routes require an authenticated session. Cookies are HTTP-only, SameSite=Strict, and Secure in production. Login attempts and uploads are rate-limited. The app validates URLs and renders editable text using DOM text nodes. Only explicitly allowed public files are served; database files, server code, seed data and environment files are private.

## Contact and metadata

The original Formspree action remains `https://formspree.io/f/xaqrvzeg`. Submission uses Fetch, retains the existing success message, and displays inline errors. Tests intercept this request and never send a real message. Confirm delivery to your inbox after deployment.

Public pages include descriptions, Open Graph and Twitter metadata, plus an SVG favicon using the existing palette. Set `SITE_URL` for absolute preview image URLs. Admin responses have noindex/nofollow and no-store headers. Public mobile navigation, keyboard focus states, semantic labels and reduced-motion support are included without replacing the visual theme.

## Deploy

Use a host that runs a long-lived Node process and provides a persistent writable disk. A purely static host cannot run this CMS.

1. Install dependencies with `npm ci --omit=dev` on Node 22.14+ (prefer Node 24 LTS).
2. Configure the environment and admin hash/session secret using setup or the host's secret settings.
3. Set `NODE_ENV=production`, `SITE_URL=https://your-domain`, and the correct `HOST`, `PORT` and `TRUST_PROXY` values.
4. Put `DATABASE_PATH` and `UPLOAD_DIR` on persistent storage. For example, `/var/data/portfolio.sqlite` and `/var/data/uploads/projects`.
5. Terminate HTTPS at a trusted reverse proxy, run `npm start`, and restart the process automatically after a crash or reboot.
6. Verify login, a draft project upload, public rendering, and contact delivery. Schedule backups.

Use one application instance with this local SQLite setup. Do not put the database on ephemeral deployment storage or share its file over a network filesystem. For multiple replicas, move persistence to a database service first.

## Verification

```sh
npm test
npm run test:browser
```

API tests use a separate temporary database and cover authentication, CSRF, origin checks, featured limits, validation, uploads, CRUD, ordering, restart persistence and private-file protection.

Browser tests run an isolated server with test-only credentials. They check public content, the mobile menu, responsive overflow, image previews, project and experience management, deletion confirmation and mocked Formspree success/failure. Screenshots go to ignored `test-results/`.

Browser tests use installed Microsoft Edge by default. On another machine, install Playwright Chromium with `npx playwright install chromium` and set `BROWSER_CHANNEL=chromium` in your shell before running the tests. Test accounts are created only by the isolated test server and never in your real portfolio database.
